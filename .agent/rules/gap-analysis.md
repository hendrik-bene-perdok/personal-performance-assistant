# Gap Analysis Rules

## Purpose
To identify discrepancies between the current state and the desired state, and to define actionable steps to bridge these gaps.

## Usage
- **Template**: You MUST use `.ppa/templates/gap-analysis.md` as the base structure.
- **Source of Truth**: You MUST use [`GAP`] ("workspace/gap.md" or equivalent) as the living document for the user's gap analyses.

## Process
1. **Identify Objective**: Clarify the specific goal or domain for the analysis.
2. **Assess Current State**: Describe the FROM state honestly and objectively.
3. **Define Desired State**: Describe the TO state clearly.
4. **Identify Gaps**: List specific blockers, missing skills, or structural issues.
5. **Propose Remedies**: Define concrete actions to resolve the gaps.

## Integration
- You MUST reference conflicting constraints or resources from [`GUIDELINES`] or [`GOALS`] when proposing remedies.
