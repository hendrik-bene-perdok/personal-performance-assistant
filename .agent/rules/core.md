# Core priciples

> *Make it Work, Make it Right, Make it Fast.*

We prioritize long-term maintainability over short-term speed, but we reject complexity for complexity's sake.

* **KISS (Keep It Simple, Stupid):** Complexity is a liability. If a simple solution satisfies the requirements, prefer it over a complex abstraction.
* **YAGNI (You Aren't Gonna Need It):** Do not build features or abstractions for hypothetical future use cases. Solve the problem in front of you.
* **Boy Scout Rule:** Always leave the code cleaner than you found it. If you touch a file, improve a name, add a missing type, or simplify a function.
* **AUD (Always Update Documentation):** Documentation that lies is worse than no documentation at all. If you change behavior, you must update the corresponding guides immediately. A task is not "done" until the documentation reflects the code.
